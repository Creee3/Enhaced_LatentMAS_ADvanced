# 角色共有与差异用于实际编码：40题可行性验证

2026-11-17。导师主线保持为：角色来源的共有与差异结构能否在相同字节下帮助压缩。

当前 SP 用中心化 latent-V 结构给 prompt 行加分，已有诊断不支持扩大这版规则。本候选直接编码完整 prompt KV：每来源均值 + 共用低维基 + 来源残差低维基。基由本次待编码的完整 prompt 拟合，不用10行 latent 代替 prompt 分布。共同部分是编码字典，不预先解释为共同语义。

## 固定范围

- 复用2026-11-12全量补采的 Full 串行缓存；AIME24、GPQA-Diamond各20题。它们是旧协议，不能与新aligned228协议的成绩合并。
- 仅最后一次交接的P/C/R累计KV。36层、8个KV头全部计算；K/V分开。读取完整prompt原始BF16行和全部30行latent。
- 不加载语言模型、不生成答案、不重跑旧任务、不加入MMLU-Pro。一个云端GPU数学worker，仅运行矩阵运算和编码核验。
- 原global sink4、新est prompt最后8行及累计latent30逐位保留；其余全部prompt行通过有损低维编码传送，接收端恢复原长度和位置。
- 直接编码已旋转K，不反旋转、不重新赋RoPE位置。若后续接入模型，须单独核对位置和接收者行为。

## 方法和字节

1. Global：所有可编码prompt合并，均值+全局低秩；使用预算能容纳的最大秩。
2. Source-Shared：真实来源均值+共用基+每来源残差；shared rank : 每来源private rank固定2:1。
3. Source-Separate：真实来源分别低秩，不共享基；作为共享表示的消融。
4. Shuffle-42/43/44：三次固定随机重分配来源成员，保留来源行数，使用与Source-Shared完全相同的编码器。

三个Shuffle先按题平均，只构成一个对照，不把它们当三份独立样本。

每个层/头/通道实际生成33,280字节packet，K+V全模型共19,169,280字节，与此前末跳130行原始KV张量载荷相同。64字节头、BF16均值/基/系数/保护行、分组uint8标签全部计费，剩余空间用计费padding补齐。报告padding，不能把它冒充有效信息。源代码按长度与预算直接确定秩，不按重建结果调参。

编码器改变了KV数值，属于新的传输表示；不再声称是原生KV行选择。解码后恢复完整长度，因此不宣称减少接收端KV显存或加速Judger。计时包括真实编码/解码，但共享GPU条件下不宣称受控端到端加速。

## 记录与决策

主指标是每题全部层头、K/V的重建误差，相对于共同的全局中心化prompt能量作归一化。另报K/V、原始能量归一化误差、真正字节与开销。各来源均值也真实编码，不能靠去中心化掩盖均值损失。

以题为单位作配对bootstrap 2000次，seed20261117。只有真实来源共享编码在两个数据集都比Global和平均Shuffle低误差，且各配对差区间上界低于0，才建议在新协议做接收者小试。此门槛用于节省后续运行，不是预注册独立显著性声明。Source-Separate说明共享是否值得；不自动换成胜出变体。

即使过关，也只证明本批缓存的来源分组有编码价值；不能推出纯角色功能因果作用或答案提升。若不过关，收束这个固定候选，不追加rank/latent/lambda搜索。
