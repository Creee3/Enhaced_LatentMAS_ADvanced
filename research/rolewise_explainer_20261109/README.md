# GGG / RRR 三次交接交互说明

直接用浏览器打开 `ggg-rrr-simulator.html`。这是一个独立离线文件，样式、计算和交互均已内嵌。

三个字母依次对应 Planner → Critic、Critic → Refiner、Refiner → Judger 三次交接。示例使用 128 维 Q/K/V，4 个 GQA query 头各取末 16 个 query，共 64 个观测。每次展示一层一个 KV 头；36 层、8 个 KV 头用于全模型 BF16 字节换算。

页面提供三次交接切换、完整历史/候选池/逐次剔除/最终交付四阶段、删除进度播放、query 与来源块切换、128 维原 K/V 检查，以及种子/层/头重新计算。

## 与本轮代码的对应

- `../rolewise_TRG_20261108/relay_select.py`：阶段映射、来源标记、保护 mask、原位置 gather。
- `../attention_control225_20261103/attention_selector.py`：G 的 attention mass 排名。
- `../role_blocks_main448_20261102/block_selector.py`：R 的公共归一化分母、四来源块目标与贪心后向删除。

G 保留注意力质量最高的 96 行 prompt，并强制保留最新发送方末 8 行。R 使用相同的注意力候选池（至多 192 行），每一步计算删除一行后的四块平均读出误差，选择误差最小的一行删除。96 是所有来源共同竞争的总预算，没有每角色固定配额。latent、sink、probe self 不参与删除；self 只用于 probe，不交给下一角色。

示例 prompt 长度为 160 / 144 / 176，每个角色追加 10 latent，最后交付长度为 110 / 120 / 130。每行全模型 K/V 字节为 `36 × 8 × 128 × 2(K,V) × 2(BF16) = 147456`。后两跳只处理前跳幸存行和当前角色新增行。选择后的 K/V 直接引用原行，原位置不重编号。

合成角色前向根据各自继承的缓存生成新的 Q/K/V 与 latent，完整演示两条路径如何逐跳分叉。示例数值来自合成数据；本轮实验结果与模型权重不包含在页面内。第二、三跳的误差分别对各自局部 probe 的完整目标计算。

## 构建与验证

在本目录执行 `python build.py` 生成独立 HTML。执行 `node test-engine.cjs` 验证预算、保护、原值引用、无行复活、共同起点、G 不依赖 V，以及独立暴力计算与 R 删除决策一致。
